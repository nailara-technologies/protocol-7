
# Protocol-7 Repository Context

## Project Overview
Protocol-7 is a distributed multi-agent system architecture implementing a harmonic computing framework. The system is based on specialized agents called "zenki" that communicate through a message routing infrastructure. Protocol-7 combines mathematical harmonic principles with practical distributed computing to create a highly modular, extensible system.

## Core Philosophy
- **Harmonic Computing**: System components follow mathematical harmonic principles, particularly division by 13
- **Agent-Based Architecture**: Functionality distributed across specialized zenki with clear responsibilities
- **Message-Passing Communication**: Components interact through a structured message protocol
- **Security-First Design**: Authentication and permissions integrated at the architectural level
- **Dynamic Configuration**: System behavior defined through executable configuration files

## Primary Components
- **Protocol-7 Interpreter**: The core execution engine that runs zenki ('bin/Protocol-7')
- **Cube Zenka**: Central message routing infrastructure connecting system components
- **V7 Zenka**: Management zenka responsible for starting and controlling other zenki
- **Module System**: Reusable code libraries providing core functionality
- **Configuration Framework**: Executable code templates defining zenka behavior

## Directory Structure
- **bin/**: Executables, scripts, and tools for system operation and management
- **configuration/**: Zenka definitions and system configuration templates
- **modules/**: Core code libraries implementing Protocol-7 functionality
- **data/**: Runtime data, storage, and supporting resources
- **docs/**: Documentation and specifications (may be limited as code is self-documenting)

## Key Technologies
- **Primary Implementation**: Perl (82.4%)
- **Performance-Critical Components**: C (3.2%)
- **User Interfaces**: Various including text-based, web, and graphical
- **Communication**: Custom protocol based on message passing

## Conceptual Framework
- **Zenki**: Specialized agents with defined roles in the system
- **Messages**: Structured communication between system components
- **Commands**: Actions that can be performed by zenki
- **Authentication**: Strong identity verification for system security
- **Permissions**: Fine-grained access control for system operations

## Usage Patterns
- System typically starts with the cube zenka for message routing
- V7 zenka manages the lifecycle of other zenki
- Client tools connect to running zenki through Unix or network sockets
- Configuration files define both static parameters and dynamic behavior

## Development Approach
- Modular design emphasizing separation of concerns
- Self-documenting code with clear naming conventions
- Harmonically aligned timestamping and identifiers
- Extensive use of Perl's flexible syntax for domain-specific languages

## Mathematical Foundations
Protocol-7 implements harmonic principles throughout its architecture, particularly in timestamping, process identification, and data structures, creating a system that inherently aligns with natural harmonic patterns.
