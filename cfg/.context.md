
# Protocol-7 Configuration Directory Context

## Purpose
This directory contains configuration and executable code templates that define Protocol-7's multi-agent system architecture. These files are directly interpreted by the Protocol-7 interpreter and define both the structure and behavior of the system's agents ['zenki'].

## Key Concepts
- **Zenki Architecture**: Files in 'zenki/' define the individual agents using a mix of configuration parameters and executable code blocks ( enclosed in '[]' brackets )
- **Harmonic Relations**: Name space of code and data structures, like the rest of the project, increasingly follows division by 13 based harmonic assertion rules where applicable, thus already aligning to later holographic storage formats in cubic space structures
- **Direct Interpretation**: The start files are interpreted directly by the Protocol-7 main program as executable code; they are not just parameter files but define actual behavior

## Directory Structure
- 'zenki/': Individual agent definitions
  - 'zenki/*/start': Entry point files that are executed directly by the Protocol-7 interpreter
  - 'zenki/cube/': Contains configuration that defines the message routing infrastructure and command availability
  - 'zenki/v7/': Contains configuration for the management zenka that can start other zenki
  - Supporting files like 'auth.users', 'auth.zenki', 'access.zenki' that define permissions and behavior

## Execution Model
- 'Protocol-7' loads a zenka's start file ( e.g., 'cfg/zenki/cube/start' )
- The interpreter pre-parses the custom syntax ( e.g., '[load_modules:<modules.load>]' ) into Perl code
- Directives in brackets '[]' are executable commands
- Parameter assignments ( e.g., 'system.zenka.name = cube' ) set system configuration
- The 'cube' zenka defines which commands are available to which users/zenki through its access control files

## Zenki Relationships
- The 'cube' zenka routes messages between other zenki according to configuration-defined rules
- The 'v7' zenka manages startup and operational control of other zenki
- Authentication and permissions are defined in files like 'auth.users', 'auth.zenki', 'access.users', and 'access.zenki'

## Mathematical Harmonics
Configuration patterns align with the mathematical harmonics that underpin the Protocol-7 framework

## Related Components
- 'bin/Protocol-7': The main interpreter that processes these configuration files
- 'modules/protocol.*': Core protocol implementation that works with these configurations
- 'modules/base.handler.command': Command handling implementation
