## task: add `create_template` parameter to kimi_dispatch and claude_dispatch

### goal

add an optional `create_template` parameter to `kimi_dispatch` and
`claude_dispatch`. when set, after the dispatch completes, fire a
`coding_summarize`-style sub-call that distills the session into a reusable
YAML context template and writes it to `data/yaml/context-templates/`.

the result: any successful dispatch can self-document by generating a template
optimized for the same kind of task in the future — capturing what worked,
what patterns were used, what to watch for, and key file references.

---

### background

`data/yaml/context-templates/` holds templates like `kimi-dispatch-workflow.yaml`
and `code-review.yaml`. each has a `name`, `descr`, `budget`, and `sections`
block. a section with `static:` contains verbatim text to inject into an AI
prompt. sections with `dynamic:` would trigger live data fetching (not needed
here — static only).

the `create_template` value is the template name slug (e.g. `"p7-mcp-tool-impl"`).
if a template with that name already exists, it is overwritten (the dispatch
just produced fresher insight).

the template is generated by the local 9B model via `coding.summarize-context`
(same path as `_do_summarize`), with a specific instruction asking it to
produce a YAML context template block.

---

### where to implement

**file**: `bin/mcp-server-p7`

**step 3 — post-dispatch template generation** (~line 1758, after the
auto_summarize block, before `my $result = ...`)

```perl
## create_template: distill this session into a reusable context template ##
if (    not length($error)
    and length( $args->{'create_template'} // '' )
    and $ext->{'name'} =~ m{^(?:claude|kimi)_dispatch$} ) {

    my $tslug = $args->{'create_template'};
    $tslug =~ s{[^a-z0-9\-]}{}gi;    ## sanitize: slug chars only ##

    if ( length $tslug ) {
        ## use the summarized output if available, else raw session text ##
        my $session_text = $output;

        my $inst
            = "you are generating a reusable YAML context template. "
            . "based on the session below, produce a template that would "
            . "help an AI agent perform the same kind of task more "
            . "efficiently in the future. capture: what the task pattern "
            . "is, key files and modules involved, conventions to follow, "
            . "common pitfalls observed, and any useful examples. "
            . "output ONLY valid YAML with this structure:\n"
            . "---\nname: $tslug\n"
            . "descr: <one line description>\n"
            . "budget: 3000\n"
            . "sections:\n"
            . "  - static: |\n"
            . "      ## <template title> ##\n"
            . "      <content here, indented 6 spaces>\n";

        my $tresult = _do_summarize( $session_text, $inst, 1200 );

        if ( defined $tresult and length $tresult ) {
            ## strip any markdown fences the model may have added ##
            $tresult =~ s{^```(?:yaml)?\n?}{}m;
            $tresult =~ s{\n?```\s*$}{}m;

            my $tpath = "$ROOT_PATH/data/yaml/context-templates/$tslug.yaml";
            if ( open my $fh, '>:encoding(UTF-8)', $tpath ) {
                print $fh $tresult;
                close $fh;
                log_msg("create_template: wrote $tpath");
            } else {
                log_msg("create_template: failed to write $tpath : $!");
            }
        } else {
            log_msg("create_template: summarization returned empty — skipped");
        }
    }
}
```

**notes**:
- `$ROOT_PATH` is already defined at the top of the file (line ~27)
- slug sanitization prevents path traversal
- `_do_summarize` is already available — reuse it, do not reinvent
- if `auto_summarize` ran first, `$output` is already the compact summary —
  this is fine and preferred (the 9B model sees clean prose, not raw JSON)
- template generation is best-effort: failure is logged, not returned as error
- `$ARG` not `@_`; lowercase comments; bracket annotations

---

### design note: future enhancement

a `create_template` on a `claude_dispatch` that itself called `kimi_dispatch`
internally would produce a template capturing the orchestration pattern —
exactly what makes nested dispatch reproducible. this is the core value:
the first time you do something novel, you get a template for free.
