Overview & Architecture

What You're Doing

Converting a dual-boot system (Windows 11 + Debian native) into a Debian-native system with Windows 11 running as a KVM virtual machine. This gives you:

  • Full Linux control: Boot into Debian by default, manage your entire system natively
  • Preserved Windows: Windows still available via virtual machine with near-native performance
  • XFS access freedom: Direct access to all XFS partitions from Linux without WSL limitations
  • Flexible storage: Shared folders between systems without filesystem compromises
  • Dual license benefit: Same Windows 11 license works both ways

Key insight: Windows runs as a regular user process on Debian. You boot into Linux every time, but can launch Windows on demand with full graphics and networking.

Prerequisites & System Analysis

Hardware Requirements

CPU Intel/AMD with VT-x/AMD-V (check: grep -E vmx|svm /proc/cpuinfo) Modern multi-core (4+ cores)
RAM 8GB total (4GB Debian + 4GB Windows) 16GB+ (8GB Debian + 8GB Windows)
Storage 160GB total disk 1TB SSD/HDD (EMTEC X160 1TB - your hardware)

Verify Hardware Virtualization Support

Run this before proceeding:

grep -E 'vmx|svm' /proc/cpuinfo && echo "✓ Virtualization enabled" || echo "✗ Virtualization disabled"

Check BIOS Settings

If the above returns nothing, reboot into BIOS and enable:

  • Intel systems: VT-x, VT-d
  • AMD systems: SVM, AMD-Vi

Your Current Partition Layout (Reference)

Critical: Back up your Windows partition before proceeding. The migration involves converting the raw partition into a virtual machine disk image. While this is reversible, a backup is essential.

Phase 1: Prepare Debian Host

1

Objective: Set up Debian as your primary native OS

Step 1.1: Boot into Native Debian

Restart your system and select Debian from the boot menu (GRUB). You should now be booting into Debian as your native OS.

Step 1.2: Update System

sudo apt update && sudo apt dist-upgrade -y

Step 1.3: Install Required Packages

sudo apt install -y \
  qemu-system-x86 \
  libvirt-daemon-system \
  libvirt-clients \
  virtinst \
  virt-viewer \
  virt-manager \
  libvirt-dev \
  bridge-utils \
  dnsmasq \
  samba \
  samba-common-bin \
  nfs-kernel-server \
  dos2unix \
  pv \
  gparted

Step 1.4: Configure User Permissions

Add your user to libvirt and kvm groups to run VMs without sudo:

sudo usermod -aG libvirt,kvm $(whoami)
# Apply group changes immediately:
newgrp libvirt
newgrp kvm
# Verify:
groups
Log out and back in after this step for changes to take full effect.

Step 1.5: Enable Libvirt Service

sudo systemctl enable libvirtd
sudo systemctl start libvirtd
sudo systemctl status libvirtd

Step 1.6: Verify KVM Installation

virsh list --all

Should show an empty list (no VMs yet) with no errors.

Step 1.7: Configure XFS Partitions (fstab)

Edit /etc/fstab to auto-mount your XFS data partitions:

sudo nano /etc/fstab

Add these lines (adjust partition numbers and mount points to your setup):

/dev/sda7  /mnt/xfs_data   xfs  defaults,nofail  0  0
/dev/sda8  /mnt/xfs_backup xfs  defaults,nofail  0  0

Create mount points:

sudo mkdir -p /mnt/xfs_data /mnt/xfs_backup
sudo mount -a
df -h | grep xfs
Your Debian host is now ready with XFS partitions accessible and KVM installed.

Phase 2: Install & Optimize KVM

2

Objective: Configure KVM for optimal Windows VM performance

Step 2.1: Enable Advanced Performance Features

Enable Huge Pages (Memory optimization)

# Check available huge pages:
cat /proc/meminfo | grep Huge

# Enable huge pages (adjust 2048 based on your RAM - 2GB per 1024 pages):
echo 2048 | sudo tee /proc/sys/vm/nr_hugepages

# Make persistent in /etc/sysctl.conf:
echo "vm.nr_hugepages = 2048" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

Optimize CPU Scheduler

sudo systemctl set-default multi-user.target  # If graphical issues arise
# Set CPU governor to performance:
echo "performance" | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor

Configure I/O Scheduler

# Use deadline or noop scheduler for virtio disks:
echo "deadline" | sudo tee /sys/block/sda/queue/scheduler

Step 2.2: Set Up Network Bridge (Optional but Recommended)

This allows the Windows VM to appear as a separate device on your network:

sudo nano /etc/network/interfaces

Add bridge configuration (example - adjust to your setup):

auto br0
iface br0 inet dhcp
    bridge_ports eth0
    bridge_stp off
    bridge_maxwait 0

Restart networking:

sudo systemctl restart networking
Alternative: Use NAT networking (easier setup, VM behind Debian's network). The scripts use NAT by default.

Step 2.3: Configure KVM Autostart

Create /etc/libvirt/hooks/daemon to manage VM lifecycle:

sudo mkdir -p /etc/libvirt/hooks
cat | sudo tee /etc/libvirt/hooks/daemon << 'EOF'
#!/bin/bash
set -e

# VM startup/shutdown hooks for libvirt daemon
# This can be used to manage VMs on system start

VNAME="Windows11"
ACTION="$1"

case "$ACTION" in
    start)
        echo "[$(date)] libvirt daemon starting"
        # Auto-start VMs marked for autostart:
        virsh autostart "$VNAME" 2>/dev/null || true
        ;;
    shutdown)
        echo "[$(date)] libvirt daemon shutting down"
        virsh shutdown "$VNAME" 2>/dev/null || true
        sleep 5
        ;;
esac
EOF
sudo chmod +x /etc/libvirt/hooks/daemon

Step 2.4: Verify KVM Configuration

virsh capabilities | grep -E 'kvm|vmx|svm'

Should show virtualization capabilities available.

KVM is now optimized with performance features enabled.

Phase 3: Migrate Windows to VM

3

Objective: Convert Windows partition to a VM disk image

Critical backup step: Before proceeding, create a full backup of your Windows partition. This migration is reversible, but you'll want a recovery point.

Step 3.1: Backup Windows Partition

# Backup Windows partition to XFS storage:
sudo dd if=/dev/sda3 bs=4M | pv | gzip > /mnt/xfs_backup/windows11_backup_$(date +%Y%m%d).img.gz

# This will take time. Verify:
ls -lh /mnt/xfs_backup/windows11_backup_*.gz

Step 3.2: Convert Windows Partition to Disk Image

Create a VM disk image from your Windows partition:

# Create directory for VM disks:
mkdir -p /mnt/xfs_data/kvm/disks

# Convert raw partition to qcow2 (copy & convert):
sudo dd if=/dev/sda3 bs=4M | pv | sudo qemu-img convert -f raw -O qcow2 /dev/stdin /mnt/xfs_data/kvm/disks/windows11.qcow2

# Verify the image:
qemu-img info /mnt/xfs_data/kvm/disks/windows11.qcow2

# Fix permissions:
sudo chown $(whoami):libvirt /mnt/xfs_data/kvm/disks/windows11.qcow2
chmod 660 /mnt/xfs_data/kvm/disks/windows11.qcow2
On your hardware (EMTEC 1TB): This conversion will take 30-60 minutes depending on the partition size and system speed. The pv command shows progress.

Step 3.3: Create VM Configuration

Save this XML as ~/windows11.xml:

cat > ~/windows11.xml << 'VMEOF'
<domain type='kvm'>
  <name>Windows11</name>
  <memory unit='GiB'>8</memory>
  <currentMemory unit='GiB'>8</currentMemory>
  <vcpu placement='static'>4</vcpu>
  <os>
    <type arch='x86_64' machine='q35'>hvm</type>
    <boot dev='hd'/>
  </os>
  <devices>
    <emulator>/usr/bin/qemu-system-x86_64</emulator>
    <disk type='file' device='disk'>
      <driver name='qemu' type='qcow2' cache='writeback'/>
      <source file='/mnt/xfs_data/kvm/disks/windows11.qcow2'/>
      <target dev='vda' bus='virtio'/>
    </disk>
    <interface type='network'>
      <mac address='52:54:00:12:34:56'/>
      <source network='default'/>
      <model type='virtio'/>
    </interface>
    <console type='pty'>
      <target type='serial'/>
    </console>
    <graphics type='spice' autoport='yes' listen='0.0.0.0'>
      <listen type='address'/>
    </graphics>
    <channel type='spicevmc'>
      <target type='virtio' name='com.redhat.spice.0'/>
    </channel>
    <redirdev bus='usb' type='spicevmc'/>
    <memballoon model='virtio'/>
    <rng model='virtio'>
      <backend model='builtin'/>
    </rng>
    <qemu:arg value='-overcommit'/>
    <qemu:arg value='cpu-pm=off'/>
  </devices>
  <qemu:commandline>
    <qemu:env name='DISPLAY' value=':0'/>
  </qemu:commandline>
</domain>
VMEOF

Step 3.4: Define the VM

virsh define ~/windows11.xml
virsh list --all

You should see Windows11 in the list (state: shut off).

Step 3.5: First Boot Test

# Start the VM:
virsh start Windows11

# Open viewer:
virt-viewer Windows11

# Monitor status:
virsh dominfo Windows11
First boot driver installation: Windows will likely require VirtIO drivers on first boot. The system drive may not be recognized. You'll need to provide drivers during installation. See "Installing VirtIO Drivers" section below.

Step 3.6: Install VirtIO Drivers in Windows VM

Pre-VM-boot preparation (on Debian):

# Download VirtIO drivers ISO:
cd /mnt/xfs_data/kvm/
wget https://releases.alt-linux.org/altlinux/p10/images/sisyphus/cloud/virtio-win.iso
# OR
wget https://fedoraproject.org/wiki/images/virtio-win-0.189.iso

During Windows boot:

  • When Windows asks for storage drivers, provide the VirtIO ISO
  • Select "Red Hat VirtIO SCSI controller" drivers
  • Windows will then see the disk
  • Complete Windows installation normally

Post-boot (inside Windows VM):

# Inside Windows as Administrator:
# Mount the VirtIO ISO from VM console
# Run: D:\virtio-win-guest-tools.exe
# Install all components:
# - QEMU Guest Agent
# - VirtIO drivers (Balloon, Network, Serial, SCSI)
# - SPICE Guest Tools
# Restart Windows
Windows is now running as a KVM virtual machine with full driver support.

Phase 4: Configure Storage & Sharing

4

Objective: Set up shared storage between host and VM

Step 4.1: Configure Samba on Debian (Host)

Samba allows Windows to access XFS partitions over network.

sudo mkdir -p /mnt/xfs_data/shared
sudo chown $(whoami):$(whoami) /mnt/xfs_data/shared
sudo chmod 755 /mnt/xfs_data/shared

# Edit Samba config:
sudo nano /etc/samba/smb.conf

Add these shares to the bottom of the config file:

[xfs_share]
   path = /mnt/xfs_data/shared
   browseable = yes
   read only = no
   create mask = 0755
   directory mask = 0755
   guest ok = no
   valid users = @libvirt

[kvm_store]
   path = /mnt/xfs_data/kvm
   browseable = yes
   read only = no
   create mask = 0755
   directory mask = 0755
   guest ok = no
   valid users = @libvirt

Enable Samba and start service:

sudo systemctl enable smbd nmbd
sudo systemctl restart smbd nmbd
sudo systemctl status smbd

Step 4.2: Mount Samba Share in Windows VM

From Windows CMD (as Administrator):

# Find Debian host IP:
ipconfig /all

# Mount Samba share (use Debian IP instead of example):
net use X: \\192.168.122.1\xfs_share /user:taeki /persistent:yes

# Verify:
net use
IP Address: If you don't know Debian's IP on the network, run from Debian: hostname -I or ip addr show

Step 4.3: Configure NFS (Alternative Faster Option)

NFS can be faster for large file transfers:

# On Debian:
sudo nano /etc/exports

Add:

/mnt/xfs_data/shared  192.168.122.0/24(rw,sync,no_subtree_check,no_root_squash)
/mnt/xfs_data/kvm     192.168.122.0/24(rw,sync,no_subtree_check,no_root_squash)

Apply and restart:

sudo exportfs -a
sudo systemctl restart nfs-kernel-server

Step 4.4: Test Storage Access

# From Debian, verify Samba:
smbclient -L localhost -U%

# From Windows VM, test share:
# In File Explorer: \\192.168.122.1\xfs_share
# Try creating a test file from both systems
XFS partitions are now accessible from Windows via Samba/NFS without any filesystem conversions.

Phase 5: Management & Automation

5

Objective: Create scripts for easy daily VM management

Step 5.1: Create Start VM Script

cat > ~/start-vm.sh << 'SCRIPTEOF'
#!/bin/bash
# Start Windows 11 VM with health checks

set -e

VMNAME="Windows11"
TIMEOUT=60
CHECK_INTERVAL=2

echo "═══════════════════════════════════════"
echo "  Windows 11 VM Startup"
echo "═══════════════════════════════════════"
echo ""

# Check if already running
if sudo virsh list --state-running | grep -q "$VMNAME"; then
    echo "✓ VM is already running"
    exit 0
fi

# Check if XFS partitions mounted
if ! mount | grep -q "/mnt/xfs_data"; then
    echo "✗ XFS partitions not mounted. Mounting..."
    sudo mount -a
fi

echo "▶ Starting $VMNAME..."
sudo virsh start "$VMNAME" 2>/dev/null

# Wait for VM to start
echo "▶ Waiting for VM to boot..."
for ((i=0; i<TIMEOUT; i+=CHECK_INTERVAL)); do
    if sudo virsh list --state-running | grep -q "$VMNAME"; then
        echo "✓ VM started successfully"
        break
    fi
    sleep $CHECK_INTERVAL
done

# Get VM IP
echo ""
echo "▶ Retrieving VM network info..."
sleep 3
VM_IP=$(sudo virsh domifaddr "$VMNAME" 2>/dev/null | grep "ipv4" | awk '{print $4}' | cut -d/ -f1)

if [ -n "$VM_IP" ]; then
    echo "✓ VM IP address: $VM_IP"
    echo ""
    echo "Access methods:"
    echo "  - Graphics console:  virt-viewer $VMNAME"
    echo "  - RDP:              remmina -c rdp://$VM_IP"
    echo "  - SSH:              ssh User@$VM_IP (if enabled)"
else
    echo "⚠ Could not determine VM IP (networking may need time to initialize)"
fi

echo ""
SCRIPTEOF
chmod +x ~/start-vm.sh

Step 5.2: Create Stop VM Script

cat > ~/stop-vm.sh << 'SCRIPTEOF'
#!/bin/bash
# Gracefully stop Windows 11 VM

set -e

VMNAME="Windows11"
TIMEOUT=120

echo "═══════════════════════════════════════"
echo "  Windows 11 VM Shutdown"
echo "═══════════════════════════════════════"
echo ""

if ! sudo virsh list --state-running | grep -q "$VMNAME"; then
    echo "✓ VM is not running"
    exit 0
fi

echo "▶ Initiating graceful shutdown..."
sudo virsh shutdown "$VMNAME"

# Wait for shutdown
echo "▶ Waiting for VM to stop..."
for ((i=0; i<TIMEOUT; i+=5)); do
    if ! sudo virsh list --state-running | grep -q "$VMNAME"; then
        echo "✓ VM stopped successfully"
        exit 0
    fi
    echo "  ⏱ Waiting... ($i/$TIMEOUT seconds)"
    sleep 5
done

# Force shutdown if timeout
echo "⚠ Graceful shutdown timeout, forcing..."
sudo virsh destroy "$VMNAME"
echo "✓ VM forced shutdown"
SCRIPTEOF
chmod +x ~/stop-vm.sh

Step 5.3: Create Backup Script

cat > ~/backup-windows.sh << 'SCRIPTEOF'
#!/bin/bash
# Backup Windows VM disk image

set -e

VMNAME="Windows11"
DISK_IMAGE="/mnt/xfs_data/kvm/disks/windows11.qcow2"
BACKUP_DIR="/mnt/xfs_backup/vm_backups"
RETENTION_DAYS=30
COMPRESSION="gzip"

mkdir -p "$BACKUP_DIR"

echo "═══════════════════════════════════════"
echo "  Windows 11 VM Backup"
echo "═══════════════════════════════════════"
echo ""

# Check if VM is running
if sudo virsh list --state-running | grep -q "$VMNAME"; then
    echo "✗ VM is running. Please stop it first: ~/stop-vm.sh"
    exit 1
fi

BACKUP_NAME="windows11_$(date +%Y%m%d_%H%M%S).qcow2.gz"
BACKUP_PATH="$BACKUP_DIR/$BACKUP_NAME"

echo "▶ Creating backup: $BACKUP_NAME"
echo "  Source: $DISK_IMAGE"
echo "  Destination: $BACKUP_PATH"
echo ""

# Backup with progress
sudo bash -c "cat '$DISK_IMAGE' | pv -tpreb | $COMPRESSION > '$BACKUP_PATH'"

# Set permissions
sudo chown $(whoami):$(whoami) "$BACKUP_PATH"

# Calculate size
SIZE=$(du -h "$BACKUP_PATH" | cut -f1)
echo ""
echo "✓ Backup completed: $SIZE"

# Cleanup old backups
echo ""
echo "▶ Cleaning up old backups (older than $RETENTION_DAYS days)..."
find "$BACKUP_DIR" -name "windows11_*.qcow2.gz" -mtime +$RETENTION_DAYS -exec rm -v {} \;

echo ""
ls -lh "$BACKUP_DIR" | tail -5
SCRIPTEOF
chmod +x ~/backup-windows.sh

Step 5.5: Create Interactive VM Management Menu

cat > ~/vm-session.sh << 'SCRIPTEOF'
#!/bin/bash
# Interactive VM session manager

clear

while true; do
    echo "═══════════════════════════════════════"
    echo "  Windows 11 VM Session Manager"
    echo "═══════════════════════════════════════"
    echo ""

    # Check VM status
    if sudo virsh list --state-running | grep -q Windows11; then
        STATUS="✓ RUNNING"
        VM_IP=$(sudo virsh domifaddr Windows11 2>/dev/null | grep "ipv4" | awk '{print $4}' | cut -d/ -f1)
        [ -n "$VM_IP" ] && STATUS="$STATUS ($VM_IP)"
    else
        STATUS="✗ STOPPED"
    fi

    echo "Status: $STATUS"
    echo ""
    echo "Options:"
    echo "  1) Start VM"
    echo "  2) Stop VM"
    echo "  3) Restart VM"
    echo "  4) Open Graphics Console (virt-viewer)"
    echo "  5) SSH to VM"
    echo "  6) List VMs"
    echo "  7) VM Info"
    echo "  8) Create Snapshot"
    echo "  9) List Snapshots"
    echo " 10) Mount XFS partitions"
    echo " 11) Backup Windows partition"
    echo "  0) Exit"
    echo ""
    read -p "Select option: " choice
    echo ""

    case $choice in
        1)
            ~/start-vm.sh
            ;;
        2)
            ~/stop-vm.sh
            ;;
        3)
            ~/stop-vm.sh
            sleep 5
            ~/start-vm.sh
            ;;
        4)
            if sudo virsh list --state-running | grep -q Windows11; then
                virt-viewer Windows11 &
            else
                echo "✗ VM not running"
            fi
            ;;
        5)
            VM_IP=$(sudo virsh domifaddr Windows11 2>/dev/null | grep "ipv4" | awk '{print $4}' | cut -d/ -f1)
            if [ -n "$VM_IP" ]; then
                ssh User@$VM_IP
            else
                echo "✗ Could not determine VM IP"
            fi
            ;;
        6)
            echo ""
            sudo virsh list --all
            echo ""
            ;;
        7)
            echo ""
            sudo virsh dominfo Windows11
            echo ""
            ;;
        8)
            snapname="manual_$(date +%Y%m%d_%H%M%S)"
            sudo virsh snapshot-create-as Windows11 --name "$snapname" --description "Created $(date)"
            echo "✓ Snapshot created: $snapname"
            ;;
        9)
            echo ""
            sudo virsh snapshot-list Windows11
            echo ""
            ;;
        10)
            echo "Mounting XFS partitions..."
            sudo mount -a
            echo ""
            mount | grep xfs
            echo ""
            ;;
        11)
            if sudo virsh list --state-running | grep -q Windows11; then
                echo "✗ Please stop the VM first"
            else
                echo "Starting backup (this may take a while)..."
                ~/backup-windows.sh
            fi
            ;;
        0)
            echo "Goodbye!"
            exit 0
            ;;
        *)
            echo "Invalid option"
            ;;
    esac

    echo ""
    read -p "Press Enter to continue..."
    clear
done
SCRIPTEOF
chmod +x ~/vm-session.sh
All management scripts are now in place. Use ~/vm-session.sh as your main interface.

Complete Scripts Reference

Essential Perl Automation Script

If you prefer Perl for automation (following your preferences):

cat > ~/vm-manager.pl << 'PERLEOF'
#!/usr/bin/perl
use strict;
use warnings;
use Getopt::Long;
use File::Spec;
use Cwd;

my %config = (
    vm_name => 'Windows11',
    disk_path => '/mnt/xfs_data/kvm/disks/windows11.qcow2',
    backup_dir => '/mnt/xfs_backup/vm_backups',
);

my $action = shift @ARGV or die "Usage: $0 {start|stop|status|backup|info}\n";

sub run_cmd {
    my ($cmd) = @_;
    print "[CMD] $cmd\n" if $ENV{DEBUG};
    system($cmd);
    return $? == 0;
}

sub virsh {
    my ($subcmd) = @_;
    return `sudo virsh $subcmd`;
}

sub vm_running {
    my $output = virsh("list --state-running");
    return $output =~ /$config{vm_name}/;
}

sub handle_start {
    print "Starting $config{vm_name}...\n";
    return if vm_running();

    # Ensure XFS mounted
    run_cmd("sudo mount -a");

    run_cmd("sudo virsh start $config{vm_name}");
    sleep 3;

    if (vm_running()) {
        print "✓ VM started\n";
        my $ip = `sudo virsh domifaddr $config{vm_name} 2>/dev/null | grep ipv4 | awk '{print \\$4}' | cut -d/ -f1`;
        chomp($ip);
        print "  IP: $ip\n" if $ip;
        return 1;
    }
    print "✗ Failed to start VM\n";
    return 0;
}

sub handle_stop {
    print "Stopping $config{vm_name}...\n";
    return unless vm_running();

    run_cmd("sudo virsh shutdown $config{vm_name}");

    for (1..120) {
        last unless vm_running();
        sleep 1;
    }

    if (vm_running()) {
        print "⚠ Graceful shutdown timed out, forcing...\n";
        run_cmd("sudo virsh destroy $config{vm_name}");
    }

    print "✓ VM stopped\n" if !vm_running();
    return 1;
}

sub handle_status {
    my $running = vm_running();
    print "Status: " . ($running ? "RUNNING" : "STOPPED") . "\n";

    my $info = virsh("dominfo $config{vm_name}");
    print $info;
}

sub handle_backup {
    print "Backing up $config{vm_name}...\n";

    if (vm_running()) {
        print "✗ VM is running. Please stop first.\n";
        return 0;
    }

    mkdir($config{backup_dir}) unless -d $config{backup_dir};

    my $timestamp = `date +%Y%m%d_%H%M%S`;
    chomp($timestamp);
    my $backup_file = "$config{backup_dir}/windows11_$timestamp.qcow2.gz";

    print "  Source: $config{disk_path}\n";
    print "  Destination: $backup_file\n";

    my $cmd = "sudo bash -c 'cat $config{disk_path} | pv -tpreb | gzip > $backup_file'";
    run_cmd($cmd);

    if (-f $backup_file) {
        my $size = -s $backup_file;
        printf("✓ Backup complete: %.2f GB\n", $size / (1024**3));
        return 1;
    }
    print "✗ Backup failed\n";
    return 0;
}

sub handle_info {
    print "VM Configuration\n";
    print "================\n";
    print "Name:   $config{vm_name}\n";
    print "Disk:   $config{disk_path}\n";
    print "Backup: $config{backup_dir}\n";
    print "\n";
    virsh("dominfo $config{vm_name}");
}

# Dispatch
SWITCH: {
    $action eq 'start'  and do { handle_start(); last SWITCH; };
    $action eq 'stop'   and do { handle_stop(); last SWITCH; };
    $action eq 'status' and do { handle_status(); last SWITCH; };
    $action eq 'backup' and do { handle_backup(); last SWITCH; };
    $action eq 'info'   and do { handle_info(); last SWITCH; };
    die "Unknown action: $action\n";
}

exit 0;
PERLEOF
chmod +x ~/vm-manager.pl
