Holographic Protocol

7-Bit Decoded State Specification

Protocol Overview

The Holographic Protocol operates on 7-bit decoded states using a cascading pattern detection system. Patterns are matched in hierarchical order, with unmatched sequences falling back to directional navigation mode.

[ 7-bit decoded state ] → Protocol Operation

Pattern Detection Order: The protocol uses progressive bit examination, building pattern types from left to right until a match is found or directional mode is used as fallback.

Pattern Detection Hierarchy

Detection Algorithm

Step-by-step pattern matching:

1. Examine first bit → if 1: Graphical Matrix Mode (6-bit)

2. If 0, examine second bit → if 01: 5×7 Pixel Mode (5-bit)

3. If 01, examine third bit → if 010: BASE32 Mode (4-bit)

4. If 011, examine fourth bit → if 0110: Monochrome Doc

5. If 0111: Color Document

6. Fallback: All other patterns → Directional Navigation

Graphical Matrix Mode

Pattern: 1 GGGGGG (6-bit operations)

Matrix Operations

The 6-bit value encodes position data or color/transparency operations within a graphical context.

5×7 Pixel Mode

Pattern: 01 GGGGG (5-bit operations)

Specialized Graphics Mode: This mode uses the same color control system as Graphical Matrix Mode but operates with 5-bit values (0-31 range).

Operation Range

With 5 bits available, this mode supports:

  • • Values 0-31: Matrix positions (subset of 5×7 grid)
  • • Note: Color control commands (48-63) are not available in this mode due to 5-bit limitation

Position Mapping:

Values 0-31 map to the first 32 positions of the 5×7 matrix (00-37 in octal)

BASE32 Character Mode

Pattern: 010 CCCC (4-bit encoding)

Encoding Scheme

This mode encodes RFC 4648 BASE32 characters for UTF-7 protocol-7 payloads using 4-bit values (0-15 range).

Character Mapping Algorithm:

• Values 0-5: value + 2 → Characters 2-7

• Values 6-15: chr(59 + value) → Characters A-J

Implementation Details

Value Range Calculation Result Characters
0-5 value + 2 2, 3, 4, 5, 6, 7
6-15 chr(59 + value) A, B, C, D, E, F, G, H, I, J
Limited Range: Due to 4-bit constraint, this mode only supports the first 16 BASE32 characters, not the full A-Z range.

Document Headers

Monochrome Documents

Pattern: 0110 DDD (3-bit specification)

Identifier: D-

Header Structure:

The remaining 3 bits after the 0110 prefix specify monochrome document attributes.

Color Documents

Pattern: 0111 DDD (3-bit specification)

Identifier: D+

Header Structure:

The remaining 3 bits after the 0111 prefix specify color document attributes.

Note: Document headers use only the 7-bit decoded state for type identification. Extended document metadata is handled by separate protocol layers.

Directional Navigation Mode

Pattern: All other patterns (fallback mode)

Structure Interpretation

When no specific pattern is matched, the full 7 bits are interpreted as directional navigation:

  • • Bits 0-1 - Directional nominator (2 bits)
  • • Bits 2-3 - Direction bits (2 bits)
  • • Bits 4-6 - Hop count (3 bits, decimal value)

Directional Nominator

Bits Mode Description
00 Forward Direct movement in specified direction
01 90° Angle Angular turn followed by movement

Direction Encoding

Bits Direction Symbol Vector
00 UP U +Y axis
10 LEFT L -X axis
01 RIGHT R +X axis
11 DOWN D -Y axis

The hop count ranges from 0-7, where 0 represents a stationary position (displayed as =).

Fallback Behavior: Any 7-bit pattern that doesn't match the specific modes above is automatically interpreted as directional navigation, ensuring all possible inputs have defined behavior.

Protocol Implementation Summary

The Holographic Protocol provides a hierarchical encoding system within a 7-bit space, enabling:

  • • Graphical operations with 6-bit precision (64 commands)
  • • Pixel manipulation with 5-bit precision (32 positions)
  • • Character encoding via 4-bit BASE32 subset (16 characters)
  • • Document classification with 3-bit type specification
  • • Spatial navigation as universal fallback with full 7-bit addressing

Key Design Principles:

• Progressive pattern matching ensures optimal bit utilization

• Fallback to directional mode guarantees universal input handling

• Hierarchical priority prevents pattern conflicts

• Each mode maximizes its available bit space for operations
