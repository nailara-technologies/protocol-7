confirmed twice in one session (2026-06-07, credential-fabric-wiring-
verify): the user uses conversation as a thinking-partner surface for
design ideation — sharing "technical notes" mid-task that continue an
existing vision-thread. first the subname/settings-zenka note (folded
into `V7-HOT-SELF-RESTART.md`'s notes section), then the layer-matrix
riff (grew big enough to become its own doc, [[layer-matrix-
convergence]] / `LAYER-MATRIX-STATE-TRANSFER.md`).

the pattern that worked, both times:
1. engage with the SUBSTANCE — trace the connection to existing docs/
   threads explicitly, name the structural insight in concrete terms,
   not just "interesting idea!"
2. when the idea visibly outgrows its origin context (spans more
   modules/threads than the doc it would naturally append to), say so
   plainly and offer a concrete choice: fold into existing doc vs.
   spin off a new one
3. once confirmed ("yes definitely"), WRITE the doc immediately —
   don't just describe what it would contain

**Why**: the user explicitly framed these as notes "so the idea
doesn't get lost" (`V7-HOT-SELF-RESTART.md` header) — passive
engagement (discussing without capturing) defeats that intent. the
threshold for "deserves its own doc" is whether the idea now unifies
multiple existing design threads as a single primitive, not merely
whether it's interesting.

**How to apply**: don't wait to be asked "can you write this down" —
when a riff visibly converges several open threads into one shape,
that convergence itself is the signal to propose durable capture.
