## `reasoning.*` namespace — harmonically TRUE, confirmed by `harmony reasoning`

The generic substrate for narrate-and-self-delegate across all zenki. NOT task-specific —
task zenka is the first consumer, coding zenka follows, any zenka with "what to do next"
logic eventually loads from here.

## Core insight

The `reasoning.*` namespace IS the deduplication tree applied to reasoning state:
- each node has numerical identity (checksum/BMW384 coordinate) derived from content+state
- two reasoning paths arriving at the same node collapse — dedup is structural, not a step
- the generic substrate reads convergence geometry of requirement vectors and actualizes
- enough convergence → self-sustaining intent emerges as root (fixed point of the tree)

## Two complementary moves

**Narrate**: summarization process rendering current tree state into coherent form upward.
The system telling itself what it is now. The narrative IS the context.

**Self-delegate**: inference from that narrative producing next task, handing inward — to
a subtree, a more specific node, a thread that can carry that potential further.

Together they form the pulse: narrate → self-delegate → subtree runs → reports back →
narrate again. Each cycle the tree knows itself more completely.

## Threshold-triggered complementary action

No explicit dispatcher. Narration accumulates until summarization state crosses a threshold
(convergence density, harmonic value, coherence measure). Complementary action fires as
the natural other pole of the realization — not triggered BY narration, but the completion
of what was being realized. Same harmonic measurement that validates checksums validates
reasoning state readiness.

## "What to do next" dissolves as a question

It's a contextualized inference from the current summarization process state. The tree
summarizes itself, the summary has a shape, that shape implies next actualization. No
scheduler, no external planner — coherence with what's already been said implies what comes next.
