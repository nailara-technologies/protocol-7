The user (Taeki) deliberately interleaves two different modes of work
across sessions: exploratory/creative feature building (e.g. an audio
entropy/waveform visualization pipeline, upgrading the povray stub into a
full async rendering pipeline) and dedicated technical-debt catch-up
sessions that clear a backlog of known-but-unaddressed bugs before it
compounds.

The 2026-07-28 jobsite session is a clean example of the latter: six
separate real bugs/gaps landed in one sitting (watchdog timer, a status
dead-end sibling fix, a new feature that surfaced two more live bugs via
its own testing, a stale model pin, a multi-waiter notification bug, an
orphaned-file bug) — none individually large, but accumulated debt that
the user explicitly framed as "catching up" so the more interesting work
elsewhere could stay unblocked. See [[project-jobsite-reports-archive-vision]]
and the jobsite entries in MEMORY-active.md for what actually landed.

**How to apply:** when a session's own findings surface tangential bugs
(discovered while testing something else, or while investigating a user's
side question), treat capturing/fixing them as in-scope and welcome, not
scope creep to push back on — this user actively wants that kind of
session. Don't assume every session needs to be feature-shaped; a
session that's entirely bug-fixes and forensics is valued on its own
terms, not just as overhead blocking "real" work.
