Kimi frequently derails into deep investigation of how AMOS7 signatures work when it sees the 4-line footer on module files. It tries to understand the checksum/hash lines rather than ignoring them.

**Why:** The signature footer looks like meaningful code to the model — it sees hex-like strings and wants to understand them.

**How to apply:** Always include a short `signatures_note` field in kimi task YAML files (or a top-level note in the `context:` block) such as:

```yaml
signatures_note: |
  Module files end with a 4-line AMOS7 signature footer starting with #,,,
  IGNORE these lines completely — they are auto-generated by the signing system
  and must not be modified or investigated. Focus only on the code above them.
```

This prevents kimi from wasting rounds on signature archaeology.
