## the trap

`bin/Protocol-7:269: use File::stat;` imports into `main::`, which is
P7's eval scope. That shadows the builtin **everywhere** — every
module, every plugin. Calling `stat($path)` returns a single
`File::stat` object (a blessed hashref), not the classic 13-element
list.

Subtle failure mode:

```perl
my ( $size, $mtime ) = ( stat($path) )[ 7, 9 ];
##  ^^ both undef ; later //0 makes them silently 0
```

No warning, no error, just zeros everywhere — took a trip through
`CORE::stat` comparison to pin down.

**Why:** P7 standardized on `File::stat::stat(...)->size/->mtime`
early, and the global `use` was kept because porting every call site
was unnecessary. Nothing in the codebase uses the plain-builtin form,
but code generated by an LLM without this context will.

**How to apply:** when writing or reviewing filesystem code for any
P7 module, prefer the OO form:

```perl
my $st = File::stat::stat($path);
my $size  = $st ? $st->size  : 0;
my $mtime = $st ? $st->mtime : 0;
```

If reviewing generated code, grep for bare `stat(` as a list — it's
almost always wrong. CORE::stat works as a last resort but is not the
project idiom.

This is the same class of gotcha as other P7 globals bin/Protocol-7
imports before modules compile [ `use English;`, various AMOS7
exports ]. Treat the set as a shared compile-time preamble when
reasoning about module scope.
