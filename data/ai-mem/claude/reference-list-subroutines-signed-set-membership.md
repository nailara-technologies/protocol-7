`src/base.list.subroutines` is the signed list of module names that
belong to the current source tree. it is kept deliberately, also as a
reminder : a per-file AMOS7 signature stays valid after the file is
deleted, so an attacker restoring a removed module [ an old, vulnerable
or withdrawn one ] would pass the signature check. only a signed
statement of the SET catches that -- the list is that statement.

**How to apply :**
- never treat a valid file signature as 'belongs here' ; membership needs
  the signed set [ the list, or later a signed checksum-tree root ]
- a replacement of the list [ e.g. a signed tree root over src/ ] must
  keep set-membership signing ; dropping the list without it reopens the
  restore attack
- the same gap in N7FS format 1 [ no signed node set ] : FILES-ZENKA.md
  open question 19 [ signed root over the node set ]
- the list is regenerated by the sign run [ new modules land in it, e.g.
  coding.input.decode in a7f46506a ] ; see [[feedback-devmod-whitelist]]
  for the manual-add case
