## Visual Repulsion as Context Isolation

### Why Repulsion Matters

```
Problem Without Repulsion:
  CPU-intensive batch job starts
  └─ Attracts nearby nodes
  └─ Pulls resources from real-time systems
  └─ Real-time latency degrades
  └─ System becomes slow everywhere

Solution With Visual Repulsion:
  CPU-intensive batch job starts
  └─ Has visual signature: high_cpu, low_latency_tolerance
  └─ Real-time systems have signature: low_cpu, high_latency_sensitivity
  └─ Visual distance = very far (opposite characteristics)
  └─ REPULSION activated
  └─ Batch job cannot colocate with real-time systems
  └─ Automatically isolated by visual incompatibility

Result: Natural context separation (no explicit policies needed)
        Incompatible workloads repel automatically
        System partitions itself by context
```

### Contextual Repulsion Patterns

```
Pattern 1: Experimental vs Stable
  Experimental zenka (trust=low):
    └─ Visual profile: untested, high_risk
    └─ REPELS from: production systems, high_trust clusters
    └─ Result: Isolated sandbox for testing

  Stable zenka (trust=high):
    └─ Visual profile: proven, reliable
    └─ ATTRACTS from: critical requests, high_priority work
    └─ Result: Core processing hub

  Sensitive data processor (security=high):
    └─ Visual profile: encrypted, restricted
    └─ REPELS from: generic systems, unknown entities
    └─ Result: Secure enclave

  Generic processor (security=low):
    └─ Visual profile: public, open
    └─ REPELS from: sensitive data systems
    └─ Result: Open data tier

Pattern 3: Fast vs Thorough
  Fast approximate processor (accuracy=low):
    └─ Visual profile: speed_optimized, rough_results
    └─ REPELS from: accuracy_critical systems
    └─ Result: Preliminary analysis tier

  Accurate processor (accuracy=high):
    └─ Visual profile: thorough, verified
    └─ ATTRACTS from: critical decisions, audits
    └─ Result: Final verification tier

Pattern 4: Real-Time vs Batch
  Real-time system (latency=ms):
    └─ Visual profile: fast_responsive, time_critical
    └─ REPELS from: batch systems, background jobs
    └─ Result: Responsive cluster

  Batch system (latency=hours):
    └─ Visual profile: throughput_optimized, patient
    └─ REPELS from: real-time systems, urgent work
    └─ Result: Background processing cluster

RESULT: Network self-partitions into contextual zones
        Each zone optimized for its purpose
        Zones repel disruption from outside
        Zero configuration needed

### Movement Algorithm

```perl
# Every timestamp, references recalculate position
<[reference.update_position]> = sub {
    my ($reference, $network_state) = @_;

    # Find all potential zenka (candidates)
    my @candidates = <[network.list_zenka]>->();

    # For each candidate, compute visual distance
    my @distances = map {
        my $zenka = $_;
        my $distance = <[visual.compute_distance]>->(
            $reference->{'visual_template'},
            $zenka->{'visual_profile'},
        );

        return {
            'zenka_id' => $zenka->{'id'},
            'distance' => $distance,
            'attraction' => 1.0 / ($distance + 0.001),  # Closer = stronger
            'compatibility' => <[visual.check_compatibility]>->($reference, $zenka),
        };
    } @candidates;

    # Filter repulsed zenka (incompatible)
    my @compatible = grep { $_->{'compatibility'} } @distances;

    # Find closest compatible zenka
    my @ranked = sort { $a->{'distance'} <=> $b->{'distance'} } @compatible;
    my $best = $ranked[0];

    if ($best) {
        $reference->{'current_target'} = $best->{'zenka_id'};
        $reference->{'distance_to_optimal'} = $best->{'distance'};
        $reference->{'attraction_strength'} = $best->{'attraction'};

        # Log movement if changed
        if ($reference->{'previous_target'} ne $best->{'zenka_id'}) {
            <[reference.log_movement]>->(
                $reference->{'id'},
                $reference->{'previous_target'},
                $best->{'zenka_id'},
                $best->{'distance'},
            );
            $reference->{'previous_target'} = $best->{'zenka_id'};
        }
    }

    return $reference;
};
```
