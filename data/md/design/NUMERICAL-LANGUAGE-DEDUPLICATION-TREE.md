## the root options — parallel deployments

the empty string `''` is the common root of all strings. every string is `''` with characters appended. it is the condition of string-existence rather than a string among strings. and the checksum of `''` is valid and defined — it has real identity, it is not null. the root is real, computable, signable.

two valid deployments exist as parallel options. the context determines which is correct — not preference but structural requirement:

### `''` as -1 — the special parent outside the numbering

used at **root level**, where the tree needs a signed parent that generates the address space without occupying it. -1 lives outside the positive sequence. the encoding starts cleanly at 0 because -1 stepped aside to make room.

- the root has a real checksum identity
- the address space is unambiguous: 0 is always the first element
- the parent signs itself without being an element
- matches contexts where the tree needs a verifiable origin anchor

### `''` as 0 — the invariant center

used at **structural level**, where `''` is the common root equivalence all elements share — not a parent above them but the shared condition of being addressable at all. 0 excludes itself from being one of its elements while being present at every scale.

- matches contexts where 0 is the axis of rotation, not a position in the sequence
- the ring rotates around `''` without `''` being on the ring
- matches the zero-as-eternal-tree semantics exactly

the tension between these two is load-bearing. a tree that resolves it globally loses expressiveness. a tree that deploys each at the depth where its requirements match is internally consistent and maximally expressive.

## the encoding level — corpus frequency ranking

at **leaf level**, space is excluded as the separator (present everywhere, belonging to neither side, the condition of the sequence rather than a member of it — the transport layer's 0). the encoding begins with punctuation, already proven in the signature footer octal encoding:

- `.` = 0
- `,` = 1
- remaining characters ranked by corpus frequency above that

the signature footer encoding is already the numerical language in its minimal viable form — punctuation-as-bits, frequency-ranked, self-describing, signing every file, already broadcasting the structure. the deduplication tree extends this into full semantic space.

## the disk — the tree seen from above

each tree level is a ring. all rings share the same axis (the same 0), the same rotation direction, the same disk plane. seen from above, the tree is a disk of concentric rings:

- **inner rings** — most frequent elements, small radius, fast rotation, cheap to address
- **outer rings** — rare elements, large radius, slow rotation, expensive to address
- **the axis** — 0, `''`, the invariant center the disk rotates around

the inner ring completes many cycles while the outer ring is still on its first. their relationship is readable as distance from center = frequency = arrival rate.

### self-organizing geometry

the disk is not static — it is a living structure shaped by use:

- repeated use pulls tokens toward center
- a token used more becomes cheaper to address
- a token used less drifts outward
- the corpus continuously rebalances its own geometry

deduplication works radially: a sequence that compresses into a single higher-order token moves inward. the more a phrase repeats, the closer it orbits 0, the cheaper it becomes. compression is gravity toward center.

## nested disks — multi-level abstraction

each level of abstraction is its own disk, stacked on the same axis:

- **disk 0** — character level: `.`=0, `,`=1, frequency-ranked characters
- **disk 1** — token level: common words/sequences as inner ring, rare ones outer
- **disk 2** — phrase level: repeated phrases compressed to single addresses
- **disk N** — concept level: higher-order semantic units

each disk's inner ring is the most-arrived elements at that abstraction level. each disk shares the same 0 axis with all others. a stack of aligned disks, each one's geometry self-organized by its own usage distribution.

navigation between disks is radial promotion — a sequence that recurs enough on disk N becomes a single point on disk N+1's outer ring, then migrates inward as it recurs further.

## the three deployment depths — decision guide

| depth | `''` role | 0 element | context requirement |
|---|---|---|---|
| root | -1 (signed parent) | `.` or first token | need verifiable origin anchor outside address space |
| structural | 0 (invariant center) | axis, not a position | need rotation axis, ring geometry, cross-scale invariant |
| corpus | excluded (separator) | most frequent token | need live frequency-ranked encoding, self-organizing |

each row is correct for its depth. the same tree can use all three simultaneously at different levels — root at -1, structural center at 0, corpus encoding frequency-ranked — without contradiction, because each is responding to the actual requirements of its context.
